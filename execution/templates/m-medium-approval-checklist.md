> 用途：TL 审批 M 级 OpenSpec 四件套时逐项打勾，确保不遗漏。  
> 使用方式：复制此文件，逐项检查。审批结论填在最后。

## Proposal 检查

- [ ] 范围和非目标是否明确
- [ ] 是否写清受影响的旧链路（或明确"无影响"）
- [ ] 是否存在应升级为 L 级的隐藏风险

## Spec 检查

- [ ] requirement 是否覆盖所有已知功能点
- [ ] 每个 requirement 是否至少有 1 个正常场景
- [ ] 是否有异常场景（校验失败、编号重复、无权限等）
- [ ] 是否有兼容性 scenario（旧页面/旧接口不受影响）
- [ ] 是否存在遗漏的 requirement

## Design 检查

- [ ] 接口路径和字段命名是否与现有模式一致
- [ ] 字段翻译约定是否符合历史惯例（不该有 xxxName 的地方没有 xxxName）
- [ ] 分页 pageSize 默认值是否与现有模块对齐
- [ ] 复用边界是否写清
- [ ] 待确认项（Pending Confirmations）是否显式标出

## Tasks 检查

- [ ] 是否包含验证/回归项
- [ ] 是否包含"确认待确认项"的前置任务
- [ ] 任务粒度是否可执行（不是抽象口号）
