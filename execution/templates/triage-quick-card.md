# 分流快速检查卡

> 用途：拿到需求后 30 秒内完成 S/M/L 分流判断。  
> 使用方式：从上到下逐条回答，命中即停。

---

## 第一步：排除高风险（如果命中任一项 → 至少 L / High Risk）

| # | 问题 | Yes / No |
|---|---|---|
| 1 | 是否涉及权限模型变更？ | |
| 2 | 是否涉及租户或数据范围逻辑变更？ | |
| 3 | 是否涉及旧接口返回结构变化？ | |
| 4 | 是否涉及事务边界或资金/账务/结算逻辑？ | |
| 5 | 是否涉及高不确定性的历史链路？ | |

**如果 1-5 中任一项 Yes → 停止，直接走 L / High Risk。**

---

## 第二步：判断是否中等（如果命中任一项 → 至少 M-Medium）

| # | 问题 | Yes / No |
|---|---|---|
| 6 | 是否涉及导出语义变化？ | |
| 7 | 影响范围是否超过单模块？ | |
| 8 | 是否需要数据库 migration 且回滚复杂？ | |
| 9 | 是否存在主数据来源或字段语义不清的情况？ | |

**如果 6-9 中任一项 Yes → 至少 M-Medium。**

---

## 第三步：确认是否微小（全部 Yes → S-Low）

| # | 问题 | Yes / No |
|---|---|---|
| 10 | 是否只涉及单字段/文案/样式的明确修改？ | |
| 11 | 以上 1-9 是否全部 No？ | |

**如果 10 和 11 都 Yes → S-Low。否则 → M-Medium。**

---

## 分流结论

- [ ] **S-Low** — 直接开发 + 最小验证
- [ ] **M-Medium** — 最小探索 + 最小 OpenSpec + 快速审批
- [ ] **L / High Risk** — 完整探索 + 完整 OpenSpec + 完整验收

**原则：不确定时宁可升级，不可降级。**
