# AI 落地资料目录说明

> 目标：把这套 `OpenSpec + Superpowers` 棕地项目 AI 开发实战资料按用途分层，服务团队和个人在需求变更、功能新增和升级改造中，更准确、更高效地完成需求分析、前后端设计、开发、联调、验收与交付。  
> 使用建议：先从 `README.md` 看目录结构，再进入对应分层。  
> 使用边界：这套资料用于约束和加速 AI 参与研发，不承诺“AI 自动正确实现需求”；最终仍以项目真实代码、真实规则、真实规格和验证证据为准。

---

## 目录分层

当前仓库采用四层结构：

1. `core/`
  作用：治理、总入口、导航、全量目录等核心必读资料。
2. `execution/`
  作用：方法论、执行手册、案例、验收、交付等落地资料。
3. `review/`
  作用：专家评审、最终结论、对外交流与复盘资料。
4. `history/`
  作用：历史讨论稿、过程稿、已被正式文档吸收的归档资料。

---

## 起手原则

正式使用这套资料前，建议先记住这 4 条：

1. 先判断治理路径，不要把所有需求都按完整重流程处理
2. 先理解旧项目约束，再让 `OpenSpec + Superpowers` 参与前后端设计和实现
3. 提示词、规格、设计、测试结论都必须尽量落到真实证据，不能依赖模糊表述
4. “完成”不等于“代码写完”，而是前后端功能、联调、验证和交付证据都闭环

> 这是一套面向棕地项目的 `OpenSpec + Superpowers` 实战推广资料包：核心文档放 `core`，落地执行资料放 `execution`，评审资料放 `review`，历史过程稿放 `history`。
