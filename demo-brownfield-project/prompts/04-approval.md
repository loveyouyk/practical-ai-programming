# 环节 4：审批提示词

> 来源：`core/AI-ADOPTION-GOVERNANCE-HANDBOOK.md` 第 5.2 节  
> 使用时机：OpenSpec 四件套生成后，TL 审批前的自检

## 实际使用的提示词（辅助 TL 自检）

```text
请帮我检查当前 equipment-management 的 OpenSpec 四件套是否满足 M-Medium 审批要求。

审批检查项：
1. proposal：范围和非目标是否明确？是否写清受影响的旧链路？
2. spec：requirement 是否覆盖所有已知功能点？是否有兼容性场景？是否有异常场景？
3. design：接口路径和字段是否与现有模式一致？字段翻译约定是否符合历史惯例？复用边界是否写清？待确认项是否标出？
4. tasks：是否包含验证和回归项？是否包含"确认待确认项"的任务？

请逐项检查，发现问题直接指出修改建议。
```

## 审批结论

审批结果：**微调后通过**

发现的问题：
1. spec 缺少"设备编号唯一性"场景 → 补充
2. tasks 缺少"确认 DictService 是否有 equipment_status"任务 → 补充
3. design 的 pageSize 默认值与 BaseTable 不一致 → 修正

以上问题都属于"小改动"，不需要退回重新生成。

## 碰撞发现

- 🔴 碰撞点 #6：方法论原版只给了"审批最少覆盖"四条文字说明，没有 checklist。实操中把这四条转成了可逐项检查的提示词。
- 🔴 碰撞点 #7：发现的三个问题都是小改动，但方法论只有"通过"和"不通过"两种结论。实际需要"微调后通过"这个中间态。
