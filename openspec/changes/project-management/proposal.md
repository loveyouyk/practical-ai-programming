# Proposal: Project Management Module

## Why

当前历史系统中缺少独立的项目管理模块能力。业务团队需要在现有后台系统中集中管理项目的基本信息，包括查询、新增、修改和导出。

目前与项目相关的信息散落在合同、客户、组织等模块中，没有独立入口进行统一管理，导致运营效率低、数据散乱、无法快速导出项目清单。

## What Changes

- 新增 `project-management` capability
- 在前端新增独立的项目管理列表页，复用现有列表页、查询区、表单弹窗和导出交互模式
- 在后端新增项目管理 CRUD 接口和按筛选条件导出接口，沿用现有 Controller / Service / Mapper 分层、统一返回体和异常处理
- 新增对应数据库表和 migration 脚本

## Scope

### In Scope

1. 项目列表查询（支持按名称、编号、状态、负责人、创建时间筛选）
2. 新增项目
3. 修改项目
4. 按当前筛选条件导出项目列表

### Out of Scope

1. 项目审批流
2. 项目操作日志中心
3. 项目关联的合同、客户、组织级联管理
4. 无关的大规模系统重构
5. 脱离现有组件体系重做前端页面

## Impact

### 前端影响

- 新增一个独立列表页和路由入口
- 新增查询区、列表表格、新增/修改表单弹窗
- 复用现有导出按钮和 loading 反馈组件
- 不改变现有页面结构、组件库、状态管理和样式体系

### 后端影响

- 新增 `ProjectController`、`ProjectService`、`ProjectMapper` 及对应数据表
- 复用现有统一返回体 `Response`、业务异常 `ServiceException`、租户上下文 `TenantContext`
- 复用现有分页组件 `PageHelper` 和导出工具
- 不改变现有接口契约和共享服务

### 兼容性

- 不修改任何现有接口的请求/响应结构
- 不修改现有权限模型，只新增项目管理相关的菜单和按钮权限
- 不修改现有租户隔离逻辑，项目管理表必须包含 `tenant_id` 字段
- 不修改现有导出语义

## Risks

1. 项目状态字段如使用新枚举，需确认是否接入现有字典服务
2. 负责人字段如来自主数据服务，需确认接口可用性和数据格式
3. 导出按筛选条件生效需前后端联调验证
4. 列表查询条件如涉及多表拼接，需确认查询性能
